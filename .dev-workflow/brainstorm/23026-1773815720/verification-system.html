서식 검증 시스템 설계

AI가 기록한 서식이 원본과 맞는지 재검증하는 루프

문제: AI가 서식을 잘못 기록할 수 있다

실제 사례: "柴村恵美子"를 초록이라고 판단 → 실제는 진한 검정

원인: 주변 텍스트(はじめに)가 초록이라 같은 색으로 추측

해결: 대조 PDF 생성 후, 원본 이미지와 나란히 비교하여 재검증

검증 루프 흐름

1. AI가 번역 + style 기록 → MD 저장

2. translate_pipeline.py → 대조 PDF 생성 (서식 적용)

3. 서식 검증 단계 (새로 추가)

→ 대조 PDF의 번역 쪽을 이미지로 렌더링

→ 원본 PDF 이미지와 나란히 비교

→ AI가 다시 보고 서식 불일치 검출

예: "시바무라 에미코 — 원본: 검정, 대조PDF: 초록 → 불일치"

4. 불일치 발견 시 → style 수정 → 대조 PDF 재생성

5. 검증 통과 → 완료

구현 방식

A

파이프라인 내장 자동 검증 (추천)

translate_pipeline.py의 build 단계에 style 검증을 추가. 대조 PDF 생성 후 자동으로 원본과 비교하여 불일치 리포트 출력. 기존 ANTI-JAPANESE 검증처럼 파이프라인에 통합.

검증 결과:
  p.8 블록 3 "시바무라 에미코"
    color: green → 원본과 불일치 (예상: black)
    ⚠️ style 수정 필요
B

별도 검증 커맨드

python src/translate_pipeline.py verify-style 커맨드를 추가. 이미 생성된 대조 PDF와 원본을 비교하는 독립 실행. 필요할 때만 수동 실행.

C

번역 스킬 내 셀프체크

AI가 style 기록 직후, 파이프라인 실행 전에 한 번 더 이미지를 보고 자기 검증. "내가 기록한 style이 맞나?" 확인 후 진행. 코드 변경 최소화.
