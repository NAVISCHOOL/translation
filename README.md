# 📖 NAVI-Translate

**나비스쿨 × 사이토 히토리 서적 번역 파이프라인**

일본어 원서 PDF를 한국어로 번역하고, 대조 PDF까지 자동 출력하는 번역 시스템입니다.

---

## 💬 어떻게 쓰나요?

안티그래비티에게 **"번역해줘"** 라고 말하면 됩니다.

```
👤 사용자: 번역해줘

🤖 안티그래비티: (자동으로 다음 청크를 탐지)
    "후아후아 2권 1~10페이지가 다음 번역 대상입니다.
     결과물: translated/antigravity/후아후아_v2/
     시작할까요?"

👤 사용자: ㅇㅇ

🤖 안티그래비티: (번역 시작)
    1단계 텍스트 추출 → 2단계 번역 초안 → 3단계 JSON 빌드 → 4단계 완료 보고
    "1~10페이지 번역 완료. 다음 청크(11~20페이지) 번역할까요?"
```

PDF/페이지를 직접 지정하면 확인 없이 바로 시작합니다:
```
👤 사용자: 후아후아 2권 1~10페이지 번역해줘
🤖 안티그래비티: (바로 번역 시작)
```

---

## 🔄 번역 워크플로우 (4단계 자동 루프)

```
┌─────────────────────────────────────────────────────────────┐
│  1단계: 텍스트 추출                                          │
│  python src/prepare_pages.py -i data/pdf/{PDF} --pages N-M  │
│  → /tmp/antigravity_pages/ (이미지 + page_texts.json)        │
├─────────────────────────────────────────────────────────────┤
│  2단계: 무결점 초안 작성                                      │
│  안티그래비티가 이미지를 직접 보고 번역                         │
│  → translated/antigravity/translation_draft_*.md             │
├─────────────────────────────────────────────────────────────┤
│  3단계: 파이프라인 빌드                                       │
│  python src/translate_pipeline.py build                      │
│  → JSON 생성 + 일본어 잔존 검증 + 대조 PDF 출력               │
├─────────────────────────────────────────────────────────────┤
│  4단계: 완료 보고 & 릴레이                                    │
│  "X~Y페이지 완료. 다음 청크 번역할까요?"                       │
└─────────────────────────────────────────────────────────────┘
```

| 항목 | 설명 |
|------|------|
| **방식** | PDF → 이미지 추출 → 안티그래비티가 직접 보고 번역 |
| **청크 단위** | 10페이지씩 (50페이지 초과 시 세션 분할) |
| **품질 검증** | Zero Omission 8항목 + 번역투 체크 + 일본어 잔존 검사 |
| **출력물** | MD 초안 → JSON → 대조 PDF (원본 좌 + 번역 우) |
| **비용** | ₩0 |

## 📝 번역 규칙

### 핵심 원칙
- **Zero Omission**: 이미지에 보이는 모든 텍스트 수록 (페이지 번호만 제외)
- **100% 한국어 출력**: 일본어/중국어 잔존 절대 금지
- **극한의 단문**: 일본어 복문을 2~3개 짧은 단문으로 분리
- **번역투 제거**: `~의` 남용, 수동태, 사역형 → 한국어 능동형으로 치환
- **감탄사/줄임표 절제**: 원문의 감탄사·말줄임표를 80% 이상 덜어냄

### 기호 규칙
- `「」` `『』` `…` → 그대로 보존 (`""` `''`로 변환 금지)
- 원문 방점(傍点) → 작은따옴표(' ')로 강조
- 루비(후리가나) → 첫 등장 시만 '번역(원어)' 병기

### 화자별 종결어미

| 화자 | 상황 | 종결어미 |
|------|------|---------|
| 사이토 히토리 | 진리·철학 | ~습니다, ~합니다 |
| 사이토 히토리 | 조언·권유 | ~해 보세요, ~거든요 |
| 시바무라 에미코 | 회고·묘사 | ~하셨습니다 (극존칭) |
| 시바무라 에미코 | 독자 가이드 | ~하세요, ~잖아요? |
| 대화체/인용 | 종조사 | ~군요, ~네요, ~지요 |
| 소제목 | — | 명사형 종결 |

### 용어집
`config/glossary.json`에 46개 항목 등록. 번역 시 자동 적용됩니다.

## ⚙️ 처음 설정

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install pymupdf fpdf2 pillow python-dotenv requests
```

번역할 PDF 파일을 `data/pdf/` 폴더에 넣어주세요.

```
data/pdf/
└── 내_번역할_파일.pdf   ← 여기에 넣으면 자동 인식됩니다
```

## 🧪 왜 OCR을 안 쓰나요?

다양한 OCR/Vision 방식을 조사하고 실험했지만, **안티그래비티가 직접 보는 게 가장 정확**했습니다.

### 조사 및 실험 기록

| 분류 | 방식 | 세로쓰기 | 결과 |
|:---:|------|:---:|------|
| **직접 실험** | | | |
| ① | PyMuPDF OCR → Qwen2.5-14B | ✗ | ❌ `景色`→`屎色` 등 오인식 다수. 60개+ 교정 테이블로도 한계 |
| ② | Gemini Vision API | ✅ | ✅ 품질 최고 (4.4초/p). 다만 안티그래비티와 동일 방식 |
| ③ | Qwen2.5-VL 7B (로컬) | △ | ❌ 반복 출력 심각, 인식률 낮음 (78초/p) |
| **Vision LLM 조사** | | | |
| ④ | MiniCPM-V 2.6 (5.8GB) | △ | OCRBench 높지만 환각 多 |
| ⑤ | LLaVA 1.6 (7B) | ✗ | 일본어 학습 데이터 부족, 성능 저조 |
| ⑥ | Moondream 2 (1.7B) | ✗ | 모델 너무 작아 일본어 미약 |
| ⑦ | GLM-OCR (~6GB) | △ | 문서 특화이나 일본어 세로쓰기 미검증 |
| **OCR 도구 조사** | | | |
| ⑧ | Ollama-OCR | △ | Vision LLM에 의존 → 동일한 한계 |
| ⑨ | olmOCR2 (Allen AI) | △ | 영어 문서 특화, 세로쓰기 미지원 |
| ⑩ | Manga OCR | ★★★★ | 세로쓰기 인식은 잘하지만 OCR만 됨 (번역 별도 필요) |
| ⑪ | Tesseract | ✗ | 세로쓰기 인식률 극히 낮음 |

> 학술 연구에서도 확인: 기존 Vision LLM들은 **세로쓰기 일본어를 가로쓰기보다 훨씬 못 읽음**.
>
> **결론**: OCR(읽기→번역 2단계)을 없애고, AI가 이미지를 직접 보고 번역하는 것이 정답.
> → **안티그래비티 하나로 심플하게.**
